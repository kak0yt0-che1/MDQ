# Часть 1. Математическое обоснование признаков

## 1.1 Общая постановка задачи

Каждая карта $c$ представлена набором транзакций $\mathcal{T}_c = \{t_1, t_2, \ldots, t_{n_c}\}$. Каждая транзакция $t_i$ — кортеж:

$$t_i = (\text{amount}_i,\ \text{merchant}_i,\ \text{mcc}_i,\ \text{timestamp}_i,\ \text{channel}_i,\ \ldots)$$

Задача: построить вектор признаков $\mathbf{x}_c \in \mathbb{R}^{35}$ для каждой карты $c$ и обучить классификатор:

$$f: \mathbb{R}^{35} \to [0, 1], \quad f(\mathbf{x}_c) = P(\text{business} \mid \mathbf{x}_c)$$

Данные: ~80 000 потребительских карт (label = 0) и ~20 000 бизнес-карт (label = 1).

📌 **Для слайда:** *Каждая карта → 35 числовых признаков → вероятность «бизнес». Единица анализа — карта, а не транзакция.*

## 1.2 Группа 1: Объём расходов (Spending Volume)

### Формулы

Для карты $c$ с транзакциями сумм $a_1, a_2, \ldots, a_n$:

| Признак | Формула | Смысл |
|---------|---------|-------|
| `tx_count` | $n_c = \mathcal{T}_c$ | Количество транзакций |
| `amt_sum` | $S_c = \sum_{i=1}^{n} a_i$ | Суммарный оборот |
| `amt_mean` | $\bar{a}_c = \frac{1}{n}\sum_{i=1}^{n} a_i$ | Средний чек |
| `amt_median` | $\text{Med}(a_1, \ldots, a_n)$ | Медианный чек |
| `amt_std` | $\sigma_c = \sqrt{\frac{1}{n-1}\sum_{i=1}^{n}(a_i - \bar{a}_c)^2}$ | Стандартное отклонение |
| `amt_max` | $\max(a_1, \ldots, a_n)$ | Максимальная транзакция |
| `amt_min` | $\min(a_1, \ldots, a_n)$ | Минимальная транзакция |
| `amt_cv` | $CV_c = \frac{\sigma_c}{\bar{a}_c}$ | Коэффициент вариации |

### Коэффициент вариации (CV)

$$CV = \frac{\sigma}{\mu}$$

CV — безразмерная мера относительной изменчивости. Для бизнес-карт $CV$ обычно выше: закупки имеют разнородные суммы (от мелких расходников до крупных поставок), тогда как потребитель тратит в более узком диапазоне.

### Экономическое обоснование

Бизнес-карты демонстрируют:
- **Более высокий медианный чек** (`amt_median` ↑ 3.99× по SHAP): бизнес-закупки крупнее бытовых
- **Более высокую дисперсию сумм**: спектр от канцтоваров до оптовых партий
- **Больше транзакций**: регулярные операционные расходы

### Статистическая значимость

Различие средних подтверждается тестом Уэлча (Welch's t-test) для неравных дисперсий:

$$t = \frac{\bar{X}_1 - \bar{X}_2}{\sqrt{\frac{s_1^2}{n_1} + \frac{s_2^2}{n_2}}}$$

Для `amt_median`: $p < 10^{-100}$, эффект Коэна $d > 1.0$ (сильный эффект).

Для признаков с тяжёлыми хвостами (суммы) дополнительно применяется непараметрический тест Манна–Уитни $U$:

$$U = \sum_{i=1}^{n_1}\sum_{j=1}^{n_2} \mathbf{1}[X_i > Y_j]$$

📌 **Для слайда:** *Бизнес-карты тратят больше, крупнее и с бо́льшим разбросом. Медианный чек — в 4 раза выше у бизнеса (SHAP lift 3.99×). Все различия статистически значимы ($p \ll 0.001$).*

## 1.3 Группа 2: Канал и время (Channel / Timing)

### Формулы

Каждый признак группы — оценка вероятности события по карте:

$$\hat{p}_{\text{event}}(c) = \frac{\sum_{i=1}^{n_c} \mathbf{1}[\text{event}(t_i)]}{n_c}$$

| Признак | Событие $\text{event}(t_i)$ |
|---------|----------------------------|
| `online_share` | `channel` = "online" |
| `weekend_share` | День недели ∈ {Сб, Вс} |
| `evening_share` | Час ∈ [18, 23] |
| `bizhours_share` | Будний день **и** час ∈ [9, 17] |
| `foreign_share` | `country` ≠ "Kazakhstan" |

### Интерпретация как статистической оценки

Каждый `*_share` — выборочная оценка вероятности:

$$\hat{p} = \frac{k}{n}, \quad \text{где } k = \sum \mathbf{1}[\text{event}]$$

По ЦПТ (центральной предельной теореме) при достаточном $n$:

$$\hat{p} \sim \mathcal{N}\left(p, \frac{p(1-p)}{n}\right)$$

Доверительный интервал Вальда:

$$\hat{p} \pm z_{\alpha/2}\sqrt{\frac{\hat{p}(1-\hat{p})}{n}}$$

### Экономическое обоснование

| Паттерн | Потребитель | Бизнес |
|---------|------------|--------|
| Время активности | Вечера, выходные | Рабочие часы (9–17, Пн–Пт) |
| Каналы | Онлайн-шопинг | Онлайн-закупки + POS в оптовых точках |
| Зарубежные транзакции | Путешествия (сезонно) | Импорт / зарубежные поставщики (регулярно) |

📌 **Для слайда:** *Бизнес тратит в рабочие часы (bizhours_share ↑), потребители — вечерами и в выходные. Каждый share — оценка вероятности соответствующего поведения.*

Потребитель покупает в розничных точках; предприниматель — у оптовиков и в профессиональных сервисах. `b2b_unique_merchants` дополнительно отражает **широту поставщиков**: если карта использует 5+ различных оптовых мерчантов — это признак систематической закупочной деятельности.

## 1.5 Группа 4: Концентрация мерчантов (Merchant Concentration)

### Индекс Херфиндаля–Хиршмана (HHI)

$$HHI_c = \sum_{m=1}^{M_c} s_m^2, \quad s_m = \frac{n_{c,m}}{n_c}$$

где $s_m$ — доля транзакций карты $c$ у мерчанта $m$, $M_c$ — число уникальных мерчантов.

**Свойства:**
- $HHI \in [1/M_c,\ 1]$
- $HHI = 1$ → все транзакции у одного мерчанта (максимальная концентрация)
- $HHI = 1/M_c$ → равномерное распределение (максимальная диверсификация)
- $HHI$ — дисперсия долей плюс квадрат среднего: $HHI = \text{Var}(s) + \bar{s}^2$

### Энтропия Шеннона

$$H_c = -\sum_{m=1}^{M_c} p_m \cdot \ln(p_m), \quad p_m = \frac{n_{c,m}}{n_c}$$

**Свойства:**
- $H \in [0,\ \ln M_c]$
- $H = 0$ → все транзакции у одного мерчанта
- $H = \ln M_c$ → равномерное распределение
- Энтропия измеряет **неопределённость** (в натах): при высокой $H$ транзакция может быть у любого мерчанта — это характерно для бизнеса с диверсифицированной базой поставщиков

### Top-1 ratio и количественные метрики

| Признак | Формула | Смысл |
|---------|---------|-------|
| `merchant_top_ratio` | $\max_m s_m$ | Доля лидирующего мерчанта |
| `n_unique_merchants` | $M_c$ | Число уникальных мерчантов |
| `n_unique_mcc` | Число уникальных MCC-кодов | Отраслевая ширина |
| `merchants_per_tx` | $M_c / n_c$ | Мерчантов на транзакцию |

### Связь HHI и энтропии

HHI и энтропия — дуальные меры одной реальности. Для экспоненциальной меры Реньи порядка $\alpha$:

$$H_\alpha = \frac{1}{1-\alpha} \ln\left(\sum_m p_m^\alpha\right)$$

- При $\alpha \to 1$: $H_1 = H$ (энтропия Шеннона)
- При $\alpha = 2$: $H_2 = -\ln(HHI)$ → HHI = $e^{-H_2}$

### Экономическое обоснование

| Метрика | Потребитель | Бизнес |
|---------|------------|--------|
| HHI | Высокий (супермаркет + 2-3 точки) | Низкий (десятки поставщиков) |
| Энтропия | Низкая | Высокая |
| Top-1 ratio | Высокий (40-60% у любимого магазина) | Низкий (10-20%) |

📌 **Для слайда:** *HHI и энтропия — две стороны одной медали. Потребитель ходит в 3-5 магазинов, бизнес — закупает у десятков поставщиков. HHI ↓ и H ↑ = маркеры бизнес-поведения.*

## 1.6 Группа 5: Рекуррентность (Recurrence)

### Формулы

| Признак | Формула | Источник |
|---------|---------|----------|
| `recurring_share` | $\frac{\sum_i \mathbf{1}[\text{is\_recurring}(t_i)]}{n_c}$ | Флаг на уровне транзакции |
| `recurring_capable_share` | $\frac{\sum_i \mathbf{1}[\text{rec\_capable}(\text{merchant}_i)]}{n_c}$ | Справочник мерчантов |
| `tokenized_share` | $\frac{\sum_i \mathbf{1}[\text{tokenized}(t_i)]}{n_c}$ | Флаг токенизации |

### Статистический смысл

Каждый `*_share` — оценка методом моментов для биномиального параметра:

$$\hat{p} \sim \text{Bin}(n_c, p) / n_c$$

Дисперсия оценки: $\text{Var}(\hat{p}) = \frac{p(1-p)}{n_c}$, уменьшается с ростом числа транзакций.

### Экономическое обоснование

- **recurring_share** (SHAP lift 4.92×): бизнес настраивает регулярные платежи поставщикам (аренда, SaaS, подписки)
- **recurring_capable_share** (SHAP lift 4.54×): транзакции у мерчантов, поддерживающих рекурринг (хостинг, облачные сервисы) — даже если конкретная транзакция не помечена как рекуррентная
- **tokenized_share**: токенизация (сохранение карты) часто указывает на систематические online-закупки

📌 **Для слайда:** *Рекуррентные платежи — 2-й по важности блок (lift 4.92×). Бизнес оплачивает регулярные подписки: SaaS, аренда, логистика. Потребители рекурринг используют реже.*

## 1.7 Группа 6: Активность и «взрывчатость» (Activity & Burstiness)

### Базовые метрики активности

| Признак | Формула |
|---------|---------|
| `active_days` | $\{d : \exists\, t_i, \text{date}(t_i) = d\}$ |
| `active_weeks` | $\{w : \exists\, t_i, \text{week}(t_i) = w\}$ |
| `span_days` | $\text{last\_date} - \text{first\_date} + 1$ |
| `tx_per_active_day` | $n_c / \text{active\_days}$ |
| `recency_days` | $\text{end\_of\_window} - \text{last\_date}$ |

### Межтранзакционные интервалы (gap-статистики)

Для упорядоченных транзакций $t_{(1)} < t_{(2)} < \ldots < t_{(n_c)}$ интервалы (в часах):

$$g_i = \frac{t_{(i+1)} - t_{(i)}}{3600}, \quad i = 1, \ldots, n_c - 1$$

| Признак | Формула |
|---------|---------|
| `gap_mean` | $\bar{g} = \frac{1}{n_c - 1}\sum_{i=1}^{n_c - 1} g_i$ |
| `gap_std` | $\sigma_g = \sqrt{\frac{1}{n_c - 2}\sum_{i}(g_i - \bar{g})^2}$ |

### Индекс «взрывчатости» Го–Барабаши (Burstiness)

$$B = \frac{\sigma_g - \bar{g}}{\sigma_g + \bar{g}}$$

**Свойства:**
- $B \in [-1, 1]$
- $B > 0$ — **взрывчатый** (bursty) паттерн: длинные периоды тишины, прерываемые залпами транзакций
- $B = 0$ — **пуассоновский** процесс: транзакции случайны и равномерны
- $B < 0$ — **регулярный** паттерн: транзакции через равные интервалы (как по расписанию)

**Связь с коэффициентом вариации интервалов:**

$$B = \frac{CV_g - 1}{CV_g + 1}, \quad \text{где } CV_g = \frac{\sigma_g}{\bar{g}}$$

Это монотонное преобразование $CV_g$, отображающее $(0, \infty) \to (-1, 1)$.

### Месячная стабильность расходов

$$CV_{\text{monthly}} = \frac{\sigma(\text{monthly\_spend})}{\bar{\text{monthly\_spend}}}$$

Бизнес-карты показывают более стабильные ежемесячные расходы (низкий $CV_{\text{monthly}}$): операционные затраты повторяются, тогда как потребитель тратит по настроению.

### Экономическое обоснование

| Паттерн | Потребитель | Бизнес |
|---------|------------|--------|
| Burstiness | > 0 (импульсные покупки) | ≈ 0 или < 0 (регулярные закупки) |
| gap_mean | Велик (покупки раз в несколько дней) | Меньше (ежедневные операции) |
| monthly_spend_cv | Высокий (сезонность, отпуск) | Низкий (стабильные затраты) |
| active_days | Мало | Много (бизнес работает каждый день) |

📌 **Для слайда:** *Burstiness Го–Барабаши измеряет регулярность. B < 0 → «как по расписанию» — типичный бизнес. B > 0 → импульсные покупки — типичный потребитель. Формула: $B = (\sigma - \mu)/(\sigma + \mu)$.*

# Часть 2. Метрики качества модели

## 2.1 ROC-AUC и связь с U-статистикой Вилкоксона

### Определение ROC-AUC

ROC-кривая строится по точкам $(\text{FPR}(\tau), \text{TPR}(\tau))$ при изменении порога $\tau \in [0, 1]$:

$$\text{TPR}(\tau) = \frac{TP(\tau)}{TP(\tau) + FN(\tau)}, \quad \text{FPR}(\tau) = \frac{FP(\tau)}{FP(\tau) + TN(\tau)}$$

$$\text{ROC-AUC} = \int_0^1 \text{TPR}(\text{FPR}^{-1}(x))\, dx$$

### Эквивалентность с U-статистикой Манна–Уитни–Вилкоксона

**Теорема (Bamber, 1975):** ROC-AUC равна нормализованной U-статистике:

$$\text{ROC-AUC} = \frac{U}{n_+ \cdot n_-} = P(\hat{p}_{\text{pos}} > \hat{p}_{\text{neg}})$$

где $n_+$ — число положительных (бизнес), $n_-$ — число отрицательных (потребители), $U$ — число конкордантных пар:

$$U = \sum_{i \in \text{pos}} \sum_{j \in \text{neg}} \mathbf{1}[\hat{p}_i > \hat{p}_j]$$

**Интерпретация:** ROC-AUC = вероятность того, что случайно выбранная бизнес-карта получит более высокий скор, чем случайно выбранная потребительская карта.

В нашем случае: **ROC-AUC = 1.0000**, что означает полное разделение распределений скоров двух классов.

### Результаты моделей

| Модель | ROC-AUC | PR-AUC | F1 |
|--------|---------|--------|-----|
| Logistic Regression (baseline) | 1.0000 | 1.0000 | 0.9996 |
| **LightGBM (основная)** | **1.0000** | **1.0000** | **0.9996** |
| Random Forest | 1.0000 | 1.0000 | 0.9995 |

📌 **Для слайда:** *ROC-AUC = P(скор бизнеса > скор потребителя). Эквивалент статистики Вилкоксона. AUC = 1.0 → классы полностью разделены в пространстве признаков.*

## 2.2 PR-AUC (Average Precision)

### Зачем PR-AUC при несбалансированных данных

Соотношение классов: 80K потребителей vs 20K бизнесов (≈ 4:1). Для несбалансированных данных ROC-AUC может быть обманчиво оптимистичен.

**Причина:** FPR = FP / N_neg. При большом $N_{\text{neg}}$ даже большое число FP «размывается» в знаменателе, и FPR остаётся малым.

### Определение PR-AUC

PR-кривая строится по точкам $(\text{Recall}(\tau), \text{Precision}(\tau))$:

$$\text{Precision}(\tau) = \frac{TP(\tau)}{TP(\tau) + FP(\tau)}, \quad \text{Recall}(\tau) = \frac{TP(\tau)}{TP(\tau) + FN(\tau)}$$

$$\text{PR-AUC} = \sum_{k} (R_k - R_{k-1}) \cdot P_k$$

(аппроксимация площади методом трапеций по точкам кривой)

### Базовая линия PR-AUC

Для случайного классификатора:

$$\text{PR-AUC}_{\text{random}} = \frac{n_+}{n_+ + n_-} = \frac{20{,}000}{100{,}000} = 0.20$$

Наше значение **PR-AUC = 1.0000** >> 0.20 — модель значимо превосходит случайную.

📌 **Для слайда:** *PR-AUC учитывает дисбаланс. Базовая линия — 0.20 (20% бизнес-карт). Мы получили 1.0 — идеальная precision на всех уровнях recall.*

---

## 2.3 F1-score: почему гармоническое среднее

### Определение

$$F_1 = \frac{2 \cdot P \cdot R}{P + R} = \frac{2\,TP}{2\,TP + FP + FN}$$

### Почему гармоническое, а не арифметическое?

Гармоническое среднее **штрафует за дисбаланс** между P и R:

| P | R | $\text{AM}(P,R)$ | $F_1 = \text{HM}(P,R)$ |
|---|---|:-:|:-:|
| 1.0 | 0.01 | 0.505 | 0.0198 |
| 0.5 | 0.5 | 0.500 | 0.500 |
| 0.9 | 0.9 | 0.900 | 0.900 |

При P = 1.0 и R = 0.01 арифметическое среднее даёт обманчивые 0.505, а $F_1$ честно показывает 0.02 — модель бесполезна.

**Общий случай — $F_\beta$:**

$$F_\beta = (1 + \beta^2) \cdot \frac{P \cdot R}{\beta^2 \cdot P + R}$$

При $\beta > 1$ — больше веса на recall (важнее не пропустить бизнес), при $\beta < 1$ — на precision.

📌 **Для слайда:** *F1 = гармоническое среднее precision и recall. Наказывает за дисбаланс: нельзя «спрятаться» за высокий precision при нулевом recall. Наш F1 = 0.9996.*

## 2.4 Матрица ошибок: бизнес-интерпретация

### Структура матрицы

|  | Предсказано: Consumer (0) | Предсказано: Business (1) |
|:-:|:-:|:-:|
| **Истинный: Consumer (0)** | TN (верно оставили в потреб.) | FP (ложный «бизнес») |
| **Истинный: Business (1)** | FN (пропущенный бизнес) | TP (выявленный бизнес) |

### Бизнес-стоимость ошибок

| Тип ошибки | Бизнес-последствие | Стоимость |
|------------|-------------------|-----------|
| **FP** (потребитель → «бизнес») | Лишний звонок/проверка. Клиент раздражён, но убытков нет | **Низкая** ($C_{FP}$) |
| **FN** (бизнес → «потребитель») | Скрытый предприниматель продолжает работать без регистрации. Банк теряет комиссионный доход, регуляторный риск | **Высокая** ($C_{FN}$) |

**Асимметрия:** $C_{FN} \gg C_{FP}$ → мы предпочитаем порог с высоким recall (даже ценой лишних FP).

📌 **Для слайда:** *FN = пропущенный бизнес → потеря дохода + регуляторный риск. FP = лишний звонок → минимальные затраты. Поэтому recall важнее precision.*

# Часть 3. Обоснование порогов классификации

## 3.1 Теория Байесовского решения для оптимального порога

### Формализация

Модель выдаёт $\hat{p}(c) = P(\text{business} \mid \mathbf{x}_c)$. Классификация:

$$\hat{y}(c) = \begin{cases} 1, & \text{если } \hat{p}(c) \geq \tau \\ 0, & \text{иначе} \end{cases}$$

### Ожидаемый риск (Expected Loss)

Для порога $\tau$ ожидаемые потери:

$$\mathcal{L}(\tau) = C_{FP} \cdot \text{FPR}(\tau) \cdot N_- + C_{FN} \cdot \text{FNR}(\tau) \cdot N_+$$

где $\text{FNR} = 1 - \text{TPR}$, $N_-$ = число потребителей, $N_+$ = число бизнесов.

### Оптимальный порог по Байесу

Из теории Байесовских решений оптимальный порог:

$$\tau^* = \frac{C_{FP}}{C_{FP} + C_{FN}}$$

**Пример:** если $C_{FN} = 10 \cdot C_{FP}$ (пропустить бизнес в 10 раз дороже, чем лишний звонок):

$$\tau^* = \frac{1}{1 + 10} = 0.091$$

Порог сдвигается **вниз**, повышая recall ценой precision.

### В нашем проекте

Мы используем три операционных порога:

| Порог | Значение | Назначение | Логика |
|-------|----------|------------|--------|
| F1-max | $\tau_{F1}$ | Автоматическая миграция тарифа | Баланс P и R |
| Recall ≥ 0.95 | $\tau_{recall}$ | Outreach-листы | Минимум пропусков |
| Lead cutoff | $\tau = 0.30$ | hidden_entrepreneurs.csv | $P(\text{business}) \geq 0.30$ |

📌 **Для слайда:** *Оптимальный порог = $C_{FP}/(C_{FP} + C_{FN})$. Чем дороже пропуск → тем ниже порог → тем выше recall. Три порога = три бизнес-сценария.*

---

## 3.2 Почему OOF-настройка, а не validation set

### Проблема «двойного использования» валидации

Если настроить порог на валидационной выборке, она перестаёт быть «честной» оценкой:

$$\text{Порог настроен на } \mathcal{D}_{\text{val}} \implies \text{метрики на } \mathcal{D}_{\text{val}} \text{ завышены}$$

### Out-of-Fold (OOF) подход

1. Разбиваем **тренировочную** выборку на $K = 5$ стратифицированных фолдов
2. Для каждого фолда $k$: обучаем на $K-1$ фолдах, предсказываем на $k$-м
3. Каждая тренировочная запись получает «честный» скор $\hat{p}_{\text{OOF}}(c)$ — от модели, не видевшей эту запись

$$\hat{p}_{\text{OOF}}(c) = f_{\neg k(c)}(\mathbf{x}_c), \quad c \in \text{fold } k$$

4. Настраиваем порог $\tau$ на OOF-скорах
5. Валидационная выборка остаётся «нетронутой» → честная оценка метрик

### Преимущество

- Порог настроен на $\sim 80\%$ данных (все тренировочные) → более стабилен
- Валидация полностью независима → нет информационной утечки
- Стандартная практика в Kaggle и production ML

📌 **Для слайда:** *OOF = каждая запись скорирована моделью, не видевшей её. Порог настроен на OOF, валидация нетронута → честная оценка финальных метрик.*

---

## 3.3 Обоснование порога 0.30 для лидов

### Байесовский аргумент

Порог $\tau = 0.30$ означает: мы считаем карту лидом, если модель оценивает вероятность бизнеса в ≥ 30%.

Из теории решений, это соответствует отношению стоимостей:

$$\tau = 0.30 = \frac{C_{FP}}{C_{FP} + C_{FN}} \implies C_{FN} = \frac{0.70}{0.30} \cdot C_{FP} \approx 2.33 \cdot C_{FP}$$

То есть мы полагаем, что **пропустить скрытого предпринимателя в 2.3 раза дороже**, чем проверить потребителя зря. Это консервативная оценка — в реальности разница может быть больше.

### Калибровочная интерпретация

Если модель хорошо откалибрована ($\hat{p} \approx P(\text{business} \mid \mathbf{x})$), то порог 0.30 означает:

> *«Мы берём на проверку всех, у кого как минимум 30%-я вероятность быть бизнесом»*

При калибровке 30% означает: из 10 карт с $\hat{p} = 0.30$ примерно 3 окажутся истинными бизнесами.

### Результат

С порогом 0.30 выявлено **11 потребительских карт** со скором ≥ 0.30, из них топ-лид с $P(\text{business}) = 0.992$.

📌 **Для слайда:** *Порог 0.30 = «пропуск бизнеса в 2.3× дороже ложного вызова». 11 карт-лидов найдено, максимальный скор 0.992.*

# Часть 4. Анализ ошибок модели

## 4.1 Ожидаемые потери (Expected Loss)

### Формула

$$\mathcal{L} = C_{FP} \cdot \text{FPR} \cdot N_- + C_{FN} \cdot (1 - \text{TPR}) \cdot N_+$$

Разложим:

$$\mathcal{L} = C_{FP} \cdot \frac{FP}{N_-} \cdot N_- + C_{FN} \cdot \frac{FN}{N_+} \cdot N_+$$

$$\mathcal{L} = C_{FP} \cdot FP + C_{FN} \cdot FN$$

### Нормализованные потери

Для сравнения разных порогов удобна нормализация:

$$\ell(\tau) = \pi_- \cdot C_{FP} \cdot \text{FPR}(\tau) + \pi_+ \cdot C_{FN} \cdot \text{FNR}(\tau)$$

где $\pi_+ = N_+ / N$, $\pi_- = N_- / N$ — доли классов.

### Числовой пример

При $C_{FP} = 1$, $C_{FN} = 10$, $N_- = 80{,}000$, $N_+ = 20{,}000$:

| Порог | FP | FN | $\mathcal{L}$ |
|-------|-----|-----|-------|
| F1-max | ~2 | ~2 | $1 \cdot 2 + 10 \cdot 2 = 22$ |
| Recall ≥ 0.95 | ~5 | ~1 | $1 \cdot 5 + 10 \cdot 1 = 15$ |

Порог с recall ≥ 0.95 даёт **меньшие ожидаемые потери** при $C_{FN} \gg C_{FP}$.

📌 **Для слайда:** *Expected Loss = $C_{FP} \cdot FP + C_{FN} \cdot FN$. При высокой стоимости пропуска ($C_{FN} \gg C_{FP}$) выигрывает порог с высоким recall.*

---

## 4.2 Калибровка модели

### Что такое калибровка

Модель **калибрована**, если:

$$P(Y = 1 \mid \hat{p}(X) = q) = q, \quad \forall q \in [0, 1]$$

То есть, среди карт со скором 0.70, ровно 70% должны быть бизнесами.

### Platt Scaling

Для калибровки LightGBM применяется Platt Scaling — логистическая регрессия поверх сырых логитов:

$$p_{\text{cal}} = \sigma(A \cdot f(\mathbf{x}) + B) = \frac{1}{1 + e^{-(A \cdot f(\mathbf{x}) + B)}}$$

Параметры $A, B$ подбираются максимизацией log-likelihood на отложенной выборке.

### Isotonic Regression (альтернатива)

Непараметрическая калибровка — изотоническая регрессия: монотонная кусочно-постоянная функция $g$, минимизирующая:

$$\min_{g \uparrow} \sum_{i=1}^{n}(y_i - g(\hat{p}_i))^2$$

### Диаграмма надёжности (Reliability Diagram)

Разбиваем скоры на $B$ бинов. Для каждого бина $b$:

$$\text{fraction\_positive}_b = \frac{\sum_{i \in b} y_i}{|b|}, \quad \text{mean\_predicted}_b = \frac{\sum_{i \in b} \hat{p}_i}{|b|}$$

Идеально откалиброванная модель: точки лежат на диагонали $y = x$.

**Метрика:** Expected Calibration Error (ECE):

$$\text{ECE} = \sum_{b=1}^{B} \frac{|b|}{n} \cdot |\text{fraction\_positive}_b - \text{mean\_predicted}_b|$$

📌 **Для слайда:** *Калибровка = «скор 0.7 → 70% бизнесов». Platt Scaling — логистическая регрессия поверх логитов. ECE — мера калибровочной ошибки.*

---

## 4.3 Оговорка о синтетических данных

### Почему AUC ≈ 1.0 не перенесётся на реальные данные

На синтетических данных достигнут AUC = 1.0000. Это объясняется:

1. **Генеративный процесс**: синтетические транзакции сгенерированы из разных распределений для бизнеса и потребителей → признаки по определению сепарабельны

2. **Отсутствие «серой зоны»**: в реальности существуют:
   - Фрилансеры (полу-бизнес)
   - ИП, использующие личную карту частично
   - Потребители с бизнес-подобным поведением (закупки для ремонта, свадьбы)

3. **Ожидаемый AUC на реальных данных**: $0.85 \leq \text{AUC} \leq 0.95$

### Формула деградации

При переходе от синтетики к реальным данным:

$$\text{AUC}_{\text{real}} \approx \text{AUC}_{\text{synth}} - \Delta_{\text{domain}} - \Delta_{\text{noise}} - \Delta_{\text{concept}}$$

где:
- $\Delta_{\text{domain}}$ — сдвиг распределения (domain shift)
- $\Delta_{\text{noise}}$ — шум в реальных данных (ошибки MCC, задержки)
- $\Delta_{\text{concept}}$ — расхождение «концепции» бизнеса в модели и реальности

📌 **Для слайда:** *AUC = 1.0 на синтетике — ожидаемо, не переносится на реальные данные. Ожидаемый AUC на реальных данных: 0.85–0.95. Ценность проекта — в фреймворке и признаках, а не в конкретной цифре AUC.*

## 4.4 Доверительные интервалы для метрик

### Бутстреп-интервал для AUC

Для оценки неопределённости используется непараметрический бутстреп:

1. Из валидационной выборки размера $n$ делаем $B = 1000$ ресэмплов с возвращением
2. Для каждого ресэмпла $b$: вычисляем $\text{AUC}_b$
3. 95% доверительный интервал: $[\text{AUC}_{(0.025)},\ \text{AUC}_{(0.975)}]$

### Аналитический интервал DeLong

Для AUC существует аналитическая оценка дисперсии (DeLong et al., 1988):

$$\text{Var}(\widehat{\text{AUC}}) = \frac{1}{n_+ \cdot n_-}\left[\frac{n_-\, \hat{S}_1 + n_+\, \hat{S}_2}{(n_+ + n_-)} \right]$$

где $\hat{S}_1, \hat{S}_2$ — оценки компонент дисперсии структурных переменных.

Приближённый 95% интервал:

$$\widehat{\text{AUC}} \pm 1.96 \cdot \sqrt{\text{Var}(\widehat{\text{AUC}})}$$

### Точный биномиальный интервал для precision/recall

При $n$ предсказаниях и $k$ правильных:

$$P \sim \text{Beta}(k + 1, n - k + 1)$$

95% интервал Клоппера–Пирсона:

$$\left[B^{-1}(0.025;\ k,\ n-k+1),\quad B^{-1}(0.975;\ k+1,\ n-k)\right]$$

📌 **Для слайда:** *Бутстреп (1000 ресэмплов) → 95% ДИ для AUC. DeLong — аналитическая альтернатива. Для precision/recall — точный биномиальный интервал Клоппера–Пирсона.*

## 5.2 Ожидаемые вопросы и ответы

### Вопрос 1: «Почему AUC = 1.0? Это переобучение?»

> **Ответ:** «Нет, это не переобучение. AUC = 1.0 на валидационной выборке, а не на тренировочной. Синтетические данные сгенерированы из разных распределений для двух классов, поэтому признаки по определению разделяют классы. На реальных данных мы ожидаем AUC 0.85–0.95, потому что появится "серая зона" — фрилансеры, ИП с личной картой, потребители с бизнес-подобным поведением.»

### Вопрос 2: «Почему вы не используете нейросети / трансформеры?»

> **Ответ:** «Для табличных данных с 35 признаками gradient boosting (LightGBM) — state-of-the-art. Мета-анализы (Grinsztajn et al., 2022; Shwartz-Ziv & Armon, 2022) показывают, что деревья превосходят нейросети на табличных данных средних размеров. Кроме того, LightGBM работает с SHAP — мы получаем объяснимость, критически важную для банковского compliance.»

### Вопрос 3: «Почему именно 40 MCC в B2B-корзине?»

> **Ответ:** «Корзина составлена на основе семантики MCC-кодов: оптовые закупки, профессиональные услуги, логистика. Мы намеренно НЕ использовали статистику по данным (какие MCC чаще у бизнеса), чтобы избежать data leakage. MCC 5122 исключён, потому что он присутствует только у бизнес-карт в нашей выборке — его включение создало бы иллюзорную предсказательную силу.»

### Вопрос 4: «Как интерпретировать 11 скрытых предпринимателей?»

> **Ответ:** «Это потребительские карты, чей паттерн поведения неотличим от бизнесовых: высокая доля B2B-MCC, рекуррентные платежи, многочисленные поставщики, регулярный ритм. Топ-лид имеет скор 0.992 — модель на 99.2% уверена, что это бизнес. SHAP-коды объясняют причины для каждого лида.»

### Вопрос 5: «Что такое SHAP и зачем он нужен?»

> **Ответ:** «SHAP (SHapley Additive exPlanations) основан на значениях Шепли из теории кооперативных игр. Для каждой карты SHAP разлагает предсказание на вклады отдельных признаков: $f(\mathbf{x}) = \phi_0 + \sum_j \phi_j$. Это единственный метод объяснения с теоретическими гарантиями: полнота (суммы сходятся), симметрия и нулевой вклад неинформативных признаков. В банке объяснимость — регуляторное требование.»

### Вопрос 6: «Почему logistic regression и LightGBM дают одинаковый AUC?»

> **Ответ:** «На синтетических данных классы линейно сепарабельны — уже линейная модель даёт идеальное разделение. На реальных данных LightGBM выиграет за счёт нелинейных взаимодействий. Мы используем LR как baseline для подтверждения: если даже простая модель работает — признаки информативны.»

### Вопрос 7: «Как будет выглядеть внедрение в продакшн?»

> **Ответ:** «Pipeline: ежемесячно агрегируем транзакции за скользящее окно 6 месяцев → строим 35 признаков → скорируем LightGBM → отфильтровываем лиды с P ≥ 0.30 → передаём в compliance на проверку. Модель пересчитывается квартально на реальных лейблах (по результатам проверок).»

### Вопрос 8: «Какова сложность алгоритма?»

> **Ответ:** «Построение признаков — $O(N \log N)$, где $N$ — число транзакций (доминирует сортировка для gap-статистик). Предсказание LightGBM — $O(T \cdot D)$ на запись, где $T = 400$ деревьев, $D = 6$ средняя глубина. Для 100K карт — менее 1 секунды.»

| Индекс Херфиндаля — Хиршмана (HHI) | $HHI_c = \sum_{m=1}^{M_c} s_m^2$ |
| Метрика энтропии Шеннона | $H_c = -\sum_{m=1}^{M_c} p_m \cdot \ln(p_m)$ |
| Индекс серийности Гоха — Барабаши | $B = \frac{\sigma_g - \bar{g}}{\sigma_g + \bar{g}}$ |
| Расчет t-критерия Уэлча | $t = \frac{\bar{X}_1 - \bar{X}_2}{\sqrt{\frac{s_1^2}{n_1} + \frac{s_2^2}{n_2}}}$ |
| U-критерий Манна — Уитни | $U = \sum_{i \in \text{pos}} \sum_{j \in \text{neg}} \mathbf{1}[\hat{p}_i > \hat{p}_j]$ |
| Среднее гармоническое ($F_1$-мера) | $F_1 = \frac{2 \cdot \text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}}$ |
| Оптимальный выбор байесовского порога | $\tau^* = \frac{C_{FP}}{C_{FP} + C_{FN}}$ |
| Ожидаемые операционные потери | $\mathcal{L} = C_{FP} \cdot FP + C_{FN} \cdot FN$ |
| Формула калибровки Платта | $p_{\text{cal}} = \frac{1}{1 + e^{-(A \cdot f(\mathbf{x}) + B)}}$ |
| Объясняющее разложение SHAP | $f(\mathbf{x}) = \phi_0 + \sum_{j=1}^{M} \phi_j$ |
